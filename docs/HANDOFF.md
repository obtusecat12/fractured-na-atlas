## 一、现在的结构

- `site/index.html` 由 `python3 site/bundle.py site/src.html site/index.html` 生成（20 MB，别手改，改 `src.html` 和各 `.js` 后重新打包）。
- 全国地图集（a1–a4.js、labels.js、fx.js）是外壳；Chrome 窗口（chrome.js）和书签（bm.js，右边缘“书签”标签）照旧。
- 游戏在 `site/game/`，以 `<iframe id="gameframe">` 嵌进外壳（见 `src.html` 开头）。直接打开 `game/index.html` 会跳回 `../index.html`。
- `site/gamehost.js`（外壳里）：
  - `FNA.toAtlas()`：游戏缩小到最小级别（z=7）或点左上角 Google Maps 标志时调用，隐藏 iframe，全国地图从纳瓦霍县拉远。
  - 全国地图上放大到纳瓦霍县（可视宽度 < 2.6 经度且中心在县界框内）自动 `FNA.toGame()`；黄色提示条里也有“返回纳瓦霍县”。

  - `FNA.started()`：登录后显示书签；登录前 `body.fna-logon` 隐藏书签和 Chrome 窗口。
- 开机动画：`site/boot.mp4`（用户提供的 Win7 启动画面），首次访问播放（localStorage `fna-boot-seen`），播完淡出露出登录屏。
- 游戏界面（2026-11-22 新版）：
  - 顶部一行 6 个大图标标签（图标 24px 在上、文字在下）：概况、人员、周边、条例、建造、财政。公文不再是标签。

  - 地图左上 `«` 按钮收起侧栏，地图占满。
  - 条例页：按钮改为“提交表决”，说明五名监事投票，3 票赞成即通过；结果写成“已通过（赞成 3 · 反对 2）”。

## 五、卡顿修复（2026-11-22，Quick 接手后第一轮）

接手人：Quick（AWS Quick）。nov-2009 内容包（120 事件 / 80 公文 / 40 广播）已在 PR #23 合进 `game-ui`。

### 原因（按影响排序）
1. **地图集在游戏后面一直在动**：默认夜景下 `a3.js` 每 83 ms、`fx.js` 每 70 ms 重画整张全国地图（夜灯、雪花、斜纹），游戏 iframe 盖住了也照跑，再叠上 `screen.js` 的全屏 `backdrop-filter`，GPU 一直忙。
2. **迷雾每秒 18 次在主线程做逐像素噪声**（约 9 万像素 × 4–5 次噪声），每帧还新建两个 ImageData、重建图案、画几百条扫描线；每次地图重画都重建遮罩（`getImageData` 回读）。
3. **拖动时每帧全量重画**：卫星图块 + 所有县界/道路顶点逐个做墨卡托（log/sin）+ 每个没见过的县各裁剪一次、画一遍“没有影像”的字。
4. **夜间路灯**每帧遍历 2.5 万个道路顶点，每盏灯新建一个径向渐变。
5. **卫星图块生成**：每块遍历全部 2 万栋房子、道路、地块；种树时每个 9 米格子都对所有住宅区多边形做点在多边形内判断；低缩放级（默认开局 z8）地面噪声每块 1.6 万次；一次 setTimeout 里连做 3 块，JPEG 同步编码。施工进度每 5% 删掉附近所有级别的图块，重新生成时出现空格。

### 改了什么
- `game.js`
  - 拖动、放置建筑时的鼠标移动：贴上一次全量画面（`SNAP`）的平移，不再全量重画；松手后全量重画。
  - 滚轮：180 ms 缩放动画（SNAP 按比例放大缩小），结束后全量重画；新级别图块没做好时用上一级/下一级缓存图块顶上。触控板增量累计满一格才换级，两次至少隔 90 ms。
  - 墨卡托坐标在点数组上按 z0 缓存（`ll._m`），每帧只做乘法。
  - “没有影像”格子预渲染成图案；没见过的县合成一条路径裁剪一次。
  - 路灯位置只算一次；光晕用预渲染小图 + globalAlpha。
  - 道路排序只做一次；`#imgdate` 只在文字变化时写。
  - `pauseAtlas()`：游戏在前台时把外壳的 `S.pending` 置真，`a3.js`/`fx.js` 的定时器就跳过重画；`FNA.toAtlas()` → `fitView` → `render()` 会把它清掉，动画自动恢复。**不用重新打包 index.html**。
  - 每日自动存档放到 `requestIdleCallback`。
- `fog.js` + 新文件 `fogworker.js`：逐像素计算移到 Web Worker（`file://` 或 Worker 出错时退回主线程，算法相同）；遮罩四周多留 48 个遮罩像素，拖动时平移遮罩，最多 120 ms 重建一次；雪花和扫描线图案只建一次；游戏切到全国地图或页面隐藏时不算。
- `map.js`：要素空间索引（约 1 km 一格）；种树先按哈希阈值筛掉 63% 的格子、住宅区先比包围盒；地面每 4 px 采样再双线性插值（低缩放级少算 4 倍，原来的 2–4 px 方块马赛克也没了）；`pump(n, done, 预算毫秒)` 按时间分批；JPEG 用 `toBlob` + `createImageBitmap` 异步（不支持时退回 `toDataURL`）；施工刷新时旧图块先留着（`stale`），新图块好了再替换。

### 测量（Quick 的云端沙箱：Node 无 JIT，比 Chrome 慢约 50–100 倍，只看前后比例）
| 项目 | 改前 | 改后 |
|---|---|---|
| 拖动一帧（地图模式 z14） | 100 ms | 8 ms |
| 拖动一帧（混合模式夜间 z15） | 105 ms | 7 ms |
| 全量重画（混合夜间 z15） | 106 ms | 65 ms |
| 生成一块卫星图（z12，开局常用） | 1628 ms | 492 ms |
| 生成一块卫星图（z15） | 1000 ms | 764 ms |
| 迷雾主线程计算 / 帧 | 116 ms | 0（在 Worker 里） |

像素对比：地图模式两张截图完全一致；混合夜景平均差 0.48/255；卫星图块平均差约 1/255（JPEG 与插值）。迷雾覆盖面积前后都是 42.7%。
