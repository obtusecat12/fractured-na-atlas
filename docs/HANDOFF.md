本文件写给接手 `game-ui` 分支（草稿 PR #22）的 AI。先读 `docs/STANDARDS.md`、`docs/GAME_MONOCACY.md`、`docs/CONTENT_GUIDE.md`。规则：走分支和草稿 PR，不直接推 main；文案用真实机构名、地名，不写解说式、意义不明的“AI 腔”。

## 一、现在的结构

- `site/index.html` 由 `python3 site/bundle.py site/src.html site/index.html` 生成（20 MB，别手改，改 `src.html` 和各 `.js` 后重新打包）。
- 全国地图集（a1–a4.js、labels.js、fx.js）是外壳；Chrome 窗口（chrome.js）和书签（bm.js，右边缘“书签”标签）照旧。
- 游戏在 `site/game/`，以 `<iframe id="gameframe">` 嵌进外壳（见 `src.html` 开头）。直接打开 `game/index.html` 会跳回 `../index.html`。
- `site/gamehost.js`（外壳里）：
  - `FNA.toAtlas()`：游戏缩小到最小级别（z=7）或点左上角 Google Maps 标志时调用，隐藏 iframe，全国地图从纳瓦霍县拉远。
  - 全国地图上放大到纳瓦霍县（可视宽度 < 2.6 经度且中心在县界框内）自动 `FNA.toGame()`；黄色提示条里也有“返回纳瓦霍县”。
  - `FNA.openMail()`：Gmail 作为 Chrome 标签页（`CWSITES.gmail`，iframe 加载 `game/gmailtab.html`，脚本 `game/gmail.js` 通过 `top.document.getElementById('gameframe').contentWindow.GAME` 读写游戏状态；处理公文按钮调用 `GAME.mailAct(i, j)`）。
  - `FNA.started()`：登录后显示书签；登录前 `body.fna-logon` 隐藏书签和 Chrome 窗口。
- 开机动画：`site/boot.mp4`（用户提供的 Win7 启动画面），首次访问播放（localStorage `fna-boot-seen`），播完淡出露出登录屏。
- 游戏界面（2026-11-22 新版）：
  - 顶部一行 6 个大图标标签（图标 24px 在上、文字在下）：概况、人员、周边、条例、建造、财政。公文不再是标签。
  - 右侧常驻数字栏 `#hud`（`game.js` 的 `meters()`，每小时刷新）：县资金、现有病例（+今日）、等待安置、物资天数、空闲人手、信任、恐慌、公文（未读数）。告急时整格变红。点任一格打开对应标签。设计依据：顶栏只放决定输赢和花钱的数字，顺序固定，告急先在顶栏出现（参考 Frostpunk：资源在顶栏、希望/不满两条对抗条、建造按钮在底部；PlayCraft “Top bar pattern”）。
  - 地图左上 `«` 按钮收起侧栏，地图占满。
  - 条例页：按钮改为“提交表决”，说明五名监事投票，3 票赞成即通过；结果写成“已通过（赞成 3 · 反对 2）”。

## 三、接下来要做的事（按优先级）

### 6. 选项效果审计（最影响可玩性）
1. 写脚本遍历 `CONTENT.events[].opts[]`、`CONTENT.mail[].acts[]`、`DATA.laws[]`、`DATA.loans`（`econ.js`），找出文字里出现 `$`、`万`、`拨款`、`补助`、`贷款`、`预算`、`grant`、`fund` 等，但 `do` 里没有 `county`/`funds` 的条目，逐条补上金额（金额要和文字一致，单位千美元）。
2. 同样检查“建”“开设”“派”这类文字是否有 `build` / 对应效果。
3. 事件弹窗（`eventDialog`，TaskDialog 命令链接）里每个选项下面用 `CONTENT.fx(o.do)` 显示效果，让玩家选之前就看到；公文按钮旁边也显示。
4. `tools/validate_content.js` 加一条警告：文字提到钱但 `do` 没有资金效果。

### 2. 界面继续简化
1. 新手第一天：只亮“概况、建造”两个标签，其它在相关事件第一次发生时解锁（加个小红点）。
2. 概况页现在仍偏长：只留“今天要处理的事”（未处理事件、承诺倒计时、未读公文、告急项），报纸、广播、州层权力挪到“人员”或单独折叠。
3. 建造页：先列 3 个推荐建筑（按当前告急项推荐：等待安置多→拖车点/收容所；物资少→仓库；病例多→接种点/隔离点），其余折叠。
4. 顶栏数字悬停显示一行原因（例如物资：每天消耗 1.3 天、补充 0.5 天）。
5. 检查 1366×768 和 1280×720 下顶栏不溢出（现在 8 格在 1366 宽刚好放下，更窄时考虑把“空闲人手”并进建造标签的角标）。

### 4. 周边页
- 在嵌入版里逐个点击周边页所有链接（放大、买物资、派外勤队、签互助协议、“派外勤 »”），确认都有反应；`data-trade`/`data-team`/`data-aid` 的处理在 `game.js` 点击委托里，选择器 `e.target.closest('a,button,...')` 已覆盖 `a`。
- 没有反应时要给反馈（钱不够、人手不够），现在“人手不够”有通知，钱不够直接 `return` 没提示，要补。

### 5. 地图手感
1. **缩放**：现在滚轮一格直接换级别、瓦片重画会闪。改成：缩放时先把当前画面按比例放大/缩小显示（像外壳 a2.js 的 `quickDraw`），200 ms 动画；新瓦片加载完再淡入（`map.js` 的 tile 缓存 + `satTiles()`/`fogTiles()`）。旧级别瓦片在新瓦片没到之前不要清掉。
2. **昼夜**：现在每小时跳一次、整体乘色。改成：按分钟插值（游戏时钟在 tick 之间按真实时间插值），黄昏偏橙、深夜偏蓝并降饱和；灯光只出现在有房屋的地方（`MAP.BLD` 里的房子随机亮窗、街道交叉口路灯），不要沿路均匀撒点；日出日落时间按霍尔布鲁克 10–12 月实际（约 6:30–7:20 日出，17:10–18:00 日落）。
3. **迷雾**（`fog.js`）：边界改成多层噪声：大尺度 fBm 决定边界走向，小尺度噪声做毛边，再加一层随时间缓慢漂移的拉丝；边界宽度随缩放变化（放大后边缘更细碎），绝不能出现直角或沿县界的直线。性能：迷雾画在离屏 canvas，只在视图变化时重算边界遮罩。
